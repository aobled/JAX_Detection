- (event) 2026-07-24: real bug found and fixed in tools/boxes_process_manual_tkinter.py::crop_bottom_zone, unrelated to the 4-step refactor (crop_bottom_zone was never touched by those steps). Aymeric reported square light-colored artifacts appearing in archive/e8ca95356acba932.jpg after holding 'x' (repeated crop, intentional workflow - crop_height=4px is small, needs several presses depending on the image). Root cause: crop_bottom_zone saved the cropped image to disk then called self.load_image() which reloaded that same file FROM disk - each subsequent crop (X11 key auto-repeat fires many times per held keypress, no debounce) started from the already-recompressed version, compounding JPEG generation loss across every press. Fixed by never reloading from disk after crop - reuse the clean in-memory cropped_image directly (same code as load_image() minus the disk read), plus quality=95/subsampling=0 as a minor bonus. Verified via simulation before (measurable compounding, ~1.25 deviation from single-compression reference) and via the REAL method after fix (0.0 deviation across 100 real crop_bottom_zone() calls). Documented in deferred-work.md.
